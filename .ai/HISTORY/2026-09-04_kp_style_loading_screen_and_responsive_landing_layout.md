# Request History: KP-Style Loading Screen + Mobile-First Responsive Landing Layout

- **Date:** 2026-09-04
- **User Request:** Inspect the loading screen implementation in the sibling `D:\awi\KP` project and build the same style of loading screen for Universal Travel Wallet. Then build a brand-new mobile-first landing layout (mobile → tablet → desktop) that looks good at every breakpoint, using Motion (Framer Motion), GSAP, and Lenis for parallax/smooth scrolling — consistent with the Soft Tactile (Claymorphism/Neumorphism) design system from ADR 005.
- **Result:**
  - **Investigated `D:\awi\KP\src\components\ui\LoadingScreen\`**: a GSAP-timeline door-split reveal (two color-washed panels sliding open), a center seam glow, a rotating/scaling logo mark, `SplitType`-driven per-character title stagger, a Canvas 2D dust-particle layer, and a film-grain CSS overlay — gated on a `kp:sceneLoaded` event for a 3D hero.
  - **Built `src/components/loading/`** (`LoadingScreen.tsx`, `LeftPanel.tsx`, `RightPanel.tsx`, `CenterSeam.tsx`, `LogoMark.tsx`, `LoaderText.tsx`, `DustParticles.tsx`, `useLoadingAnimation.ts`, `loading.css`), adapting the same door-split/seam/logo/particle mechanics to Universal Travel Wallet's violet/purple brand: panels use the design system's `--background-gradient` plus a violet/indigo ambient wash (no blue/orange split, no neon), the seam glows violet on both sides, the logo mark renders the actual `/logo.png` brand asset, dust particles are single-hue violet, and the title uses a plain fade/slide (no `SplitType` dependency — kept the bundle lighter per Rule 25, still reads as premium). Removed the KP `#s1`/3D-scene-wait logic entirely since there's no 3D hero yet; the timeline runs on a fixed, `prefers-reduced-motion`-aware schedule and dispatches `utw:loaded` instead of `kp:loaded`.
  - **Replaced the Liquid-Glass-era components** with ones matching ADR 005: `SoftCard.tsx` and `SoftButton.tsx` (new, opaque, convex/concave dual-shadow surfaces) and a rewritten `GradientIconTile.tsx` (pastel clay gradient roles — primary/lavender/mint/pink/peach/sky/coral/amber/teal — instead of the old saturated blue/cyan/purple set). Deleted the superseded `GlassCard.tsx`/`GlassButton.tsx`.
  - **Rewrote `globals.css` and `tailwind.config.ts`** to the ADR-005 token set: dark-purple night canvas (`#15101F`→`#0F0B18`), white day canvas (`#FFFFFF`→`#F1EDFC`, via a `.light` class, not yet wired to a toggle UI), violet accent (`#9B8CFF` night / `#7C6FEF` day), dual-tone clay/neumorphic shadow utility classes (`.shadow-clay-convex`, `-elevated`, `-floating`, `-concave`, `.press-convex-concave`), pastel `bg-gradient-clay-*` utilities, and the bumped-up radius scale from the design system.
  - **Built `src/components/providers/SmoothScrollProvider.tsx`**: Lenis smooth-scroll driven entirely by `gsap.ticker` (single driver, no duplicate rAF loop), with `lenis.on('scroll', ScrollTrigger.update)` so scroll-linked (parallax) GSAP animations stay in sync; skips entirely under `prefers-reduced-motion`.
  - **Built a new mobile-first landing page** (`src/components/landing/`: `Hero.tsx`, `FeatureGrid.tsx`, `HowItWorks.tsx`, `CTASection.tsx`, `Footer.tsx`, assembled in `src/app/page.tsx`): base styles target mobile (single column, stacked CTAs), `sm:`/`lg:` breakpoints progressively add columns and enlarge type/spacing (tablet 2-column feature grid, desktop 3-column). Hero has a GSAP `ScrollTrigger`-scrubbed parallax background wash (soft gradient blob, no glow/neon) and Motion `whileInView` entrance animations elsewhere. Feature/step content maps to the frozen spec's actual capabilities (multi-currency, wallets, splitting, settlement, budget, offline) rather than placeholder copy.
  - **Fixed a `next/font/google` gap**: `--font-geist-sans` was referenced in CSS but never bound to a real font in `layout.tsx` (a Phase-1 baseline gap, not something this session introduced), causing headings to render in the browser's serif fallback. Bound `Inter` (metric-compatible Geist substitute — true Geist isn't in Next 14's `next/font/google`) to that CSS variable in `layout.tsx`.
  - **Fixed a dependency conflict surfaced by installing `gsap`/`lenis`**: `npm install` resolved `framer-motion@12.4.7`'s `motion-dom` peer to a caret-range-violating `12.43.0` that broke several exports (`GroupPlaybackControls`, `attachTimeline`, `capturePointer`, `isBezierDefinition`, ...). Pinned `motion-dom` to the compatible `12.4.5` via a package.json `overrides` entry (not a direct dependency) rather than bumping `framer-motion` to a new major version.
  - **Verified**: `npm run typecheck`, `npm run lint`, `npm run test` (25 tests, unaffected domain suite), and `npm run build` all pass cleanly. Visually verified in the Browser pane at mobile (375px), tablet (768px), and desktop (1280px) — confirmed via both screenshots and DOM/computed-style inspection (grid column counts, element counts) after a couple of screenshot-capture timing artifacts (mid-animation frames, viewport-vs-screenshot-crop mismatch at 1280px) turned out not to be real bugs.
- **Scope / follow-ups not done in this pass:** no day/night theme toggle UI was built (the `.light` CSS class exists but nothing switches it yet); no PWA manifest icon updates beyond what already existed; the deep financial engines (expense entry, exchange recording, settlement, negotiation, cash counter, budget, backup/restore) remain unbuilt, consistent with prior scope boundaries.
